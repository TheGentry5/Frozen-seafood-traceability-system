## 0. 通用约定（先读，任何方法都要遵守）

| 约定 | 内容 |
| --- | --- |
| 状态/类型常量 | `StatusConst`（`farm`=待发布1/已发布2/已下架3；链条模块=新建1/待确认2/已确认3/已下架4；`node_type`=1养殖2加工3批发4零售） |
| 统一返回 | 成功由 Controller 包 `Result.ok`，失败一律抛 `BizException(code,msg)`；`code` 用 `BizCode`（400 参数/业务、401 未登录、403 越权、409 重复、500 兜底） |
| 登录身份 | 从 `AuthContext` 取：`AuthContext.isAdmin() / nodeId() / nodeType()`；Service 内校验归属（`checkOwner`）否则 403 |
| 密码 | 存 **MD5 小写 32 位**：`DigestUtils.md5DigestAsHex(pwd.getBytes(StandardCharsets.UTF_8))`，初始化数据密码均为 `123456` |
| 事务 | 状态流转/进场确认/溯源码生成方法加 `@Transactional`（readOnly 聚合查询加 `readOnly=true`） |
| 唯一性双保险 | 前端 Blur 校验 + 数据库唯一索引；捕获 `DuplicateKeyException` 由全局处理器统一转 409（生成溯源码时需自行重试，见任务 9） |
| 联表瞬态字段 | 实体上 `@TableField(exist=false)` 的 `nodeName / inNodeName / inBatchCode / nodeTypeName / provinceName / cityName` 必须由自定义 XML SQL 别名字段填充，否则页面显示为空 |

## 任务 1：登录与用户（AuthServiceImpl）

| 待实现方法 | 接口 | 实现要点 | 参考 |
| --- | --- | --- | --- |
| `login(nodeCode, password)` | POST `/api/login` | ① 按 `node_code` 查 `node_info`；② 为空或密码 MD5 不匹配 → 400"登录编码或密码错误"；③ `status=2` → 400"该企业已被停用"；④ 组装 `Principal{type=NODE,id,code,name=nodeName,nodeType}`，`tokenStore.create`，返回 `{token, user}`（user 去掉 password 字段，联出省/市中文名可选） | 实施 §6.1、§4.3 |
| `adminLogin(username, password)` | POST `/api/admin/login` | 同左逻辑查 `admin` 表；`Principal{type=ADMIN,...}`；返回 `{token, role:"ADMIN", username}` | §6.1 |
| `currentUser()` | GET `/api/user/info` | 由 `AuthContext` 定位 `node_id` 查 `node_info`（NODE 才允许；ADMIN 可返回提示或空），去掉 password | §6.1 |
| `updatePassword(oldPwd,newPwd)` | POST `/api/user/updatePwd` | 校验旧密码（MD5 比较）→ 400 提示；新密码非空 → 更新为新密码 MD5；随后作废当前 token（`TokenStore.remove(当前请求token)`，token 需由 Controller 或拦截器透传） | §6.1 |

## 任务 9：Mapper XML 自定义 SQL 填充（resources/mapper/*.xml）

当前均为空壳，直接照 `docs/开发实施文档.md 附录 D` 的语句模板落地，注意点：

| 文件 | 需实现的方法 | 关键 SQL 要求 |
| --- | --- | --- |
| `NodeInfoMapper.xml` | `selectPageWithArea`、`upstreamList`、`selectMonthTrend`、`selectProvinceDist`、`selectTypeDist` | 分页方法在 Mapper 接口入参 `IPage<?> page`（XML 无需写 limit）；`upstreamList` 动态 `<if>` 省市；统计用 `GROUP BY`，`monthTrend` 缺月补 0 在 Java 侧完成 |
| `FarmBatchMapper.xml` | `selectPageForNode`、`selectReleasedByNode` | 列表默认 `status<>4`（farm 无 4，本表不需要该条件）；`LEFT JOIN node_info` 填 `node_name` |
| `ProcBatchMapper.xml` | `selectPageForNode`、`waitConfirmList`、`selectSelectableByNode` | 列表 `LEFT JOIN farm_batch/farm?`：`in_batch_id→farm_batch.batch_code`（=inBatchCode）、`in_node_id→node_info.node_name`（=inNodeName）；`waitConfirmList` join `node_info n ON b.node_id=n.id` 填 `node_name`，条件 `in_node_id=#{inNodeId} AND status=2`，keyword 模糊 `n.node_name` |
| `WholBatchMapper.xml` | `selectPageForNode`、`waitConfirmList`、`selectSelectableByNode` | 同上，上游表换 `proc_batch` |
| `RetaBatchMapper.xml` | `selectPageForNode`、`waitConfirmList`、`selectSelectableByNode`、`selectByTraceCode` | 上游表换 `whol_batch`；`selectByTraceCode`：`WHERE trace_code=#{traceCode}` join 批发 `node_info` 填 `inNodeName` |

> 字段映射已开 `map-underscore-to-camel-case`，XML 别名字段写实体瞬态字段对应列名即可（如 `n.node_name AS in_node_name` → `inNodeName`）。
